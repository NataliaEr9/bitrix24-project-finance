# Финансы проектов для Битрикс24

Веб-приложение для ручного совместного учёта доходов и расходов по проектам внутри Битрикс24.

## Что реализовано

- проекты и команды сотрудников;
- доходы и расходы по каждому проекту;
- обязательные статьи расходов:
  - внешние программисты;
  - внутренние программисты;
  - расходы на ИИ;
  - аренда сервера;
  - дивиденды;
- базовая статья дохода «Доход по проекту»;
- ручное добавление пользовательских статей доходов и расходов;
- создание, редактирование и удаление финансовых операций;
- финансовые показатели по проекту и по всем проектам:
  - доходы;
  - расходы;
  - прибыль;
  - рентабельность;
- фильтрация журнала операций;
- демо-режим при запуске вне Битрикс24;
- автоматическая первичная настройка хранилища.


## Цветные статусы проектов

Статус рассчитывается автоматически по фактическим операциям и не требует ручного заполнения:

- **Прибыльный** — прибыль неотрицательная, рентабельность 20% и выше;
- **На контроле** — проект не убыточный, но рентабельность ниже 20%;
- **Убыточный** — расходы превышают доходы;
- **Нет данных** — по проекту ещё нет финансовых операций.


## Архитектура

Приложение сделано как **статическое локальное приложение Битрикс24**.

Отдельный backend и отдельная СУБД не нужны. Данные хранятся в трёх универсальных списках Битрикс24:

1. `PF · Проекты`
2. `PF · Статьи`
3. `PF · Операции`

Это позволяет нескольким сотрудникам работать с одними и теми же данными внутри портала и существенно упрощает запуск тестового проекта.

### Почему суммы хранятся в копейках

Финансовые суммы переводятся в целое число копеек до сохранения. Например:

`1234,56 ₽ → 123456`

Так расчёты прибыли не зависят от ошибок двоичной арифметики JavaScript с дробными числами.

## Формулы

**Прибыль**

`Прибыль = Доходы − Расходы`

**Рентабельность**

`Рентабельность = Прибыль / Доходы × 100%`

Если доход равен нулю, рентабельность не вычисляется и в интерфейсе показывается `—`.

В `financial.js` дополнительно рассчитывается ROI:

`ROI = Прибыль / Расходы × 100%`

Он оставлен в расчётном модуле для возможного развития интерфейса.

## Быстрый запуск без Битрикс24

Откройте `index.html` в браузере.

Если страница запущена как самостоятельная страница, а не во фрейме Битрикс24, приложение автоматически включит демо-режим с тестовыми проектами и сохранением изменений в `localStorage`.

Это позволяет быстро проверить интерфейс и финансовую логику без настройки портала.

## Запуск внутри Битрикс24

1. Создайте ZIP-архив, в корне которого находятся:
   - `index.html`
   - `styles.css`
   - `financial.js`
   - `app.js`
2. В Битрикс24 откройте раздел разработчика локальных приложений.
3. Создайте **статическое локальное приложение** и загрузите ZIP.
4. Выдайте приложению права:
   - `lists` — работа с универсальными списками;
   - `user_brief` (или более широкий `user`) — отображение сотрудников.
5. Первый запуск выполните администратором.
6. Нажмите **«Инициализировать приложение»**.
7. После создания списков приложение готово для совместной работы сотрудников.

При инициализации приложению создаются списки с правом изменения для всех пользователей портала и полным правом для администратора, выполнившего настройку.


## Двусторонняя синхронизация со списками Битрикс24

Приложение и универсальные списки работают с одними и теми же записями. Это не отдельные копии данных.

- запись, созданная в приложении, сразу создаётся/обновляется в `PF · Проекты`, `PF · Статьи` или `PF · Операции`;
- запись, созданная вручную в списке Битрикс24, попадает в приложение после нажатия **«Обновить данные»** или перезагрузки страницы;
- при редактировании операции в приложении одновременно обновляются удобные поля списка и скрытые технические поля совместимости.

Для ручной работы в списках приложение создаёт понятные поля:

- в `PF · Статьи`: **Тип статьи → Доход / Расход**;
- в `PF · Операции`: **Проект**, **Тип → Доход / Расход**, **Статья**, **Сумма, ₽**, **Дата**, **Комментарий**.

Старые поля `PROJECT_ID`, `TYPE`, `CATEGORY_ID`, `AMOUNT_CENTS` остаются служебными и скрываются из стандартных форм. Это сохраняет совместимость с уже созданными данными. При первом открытии обновлённой версии администратором существующие записи автоматически заполняются новыми удобными полями.

## Ограничения тестовой версии

- Валюта интерфейса — RUB.
- Разграничение доступа внутри отдельных проектов не реализовано: сотрудники, имеющие доступ к спискам приложения, видят общий финансовый учёт.
- Для промышленной версии стоит добавить аудит изменений, архивирование проектов, экспорт, периоды отчётности и проектные роли.

## Что можно развить

- графики P&L по месяцам;
- бюджет / факт;
- ROI и точка безубыточности;
- экспорт в Excel;
- связь проекта со сделкой или смарт-процессом CRM;
- уведомления при превышении бюджета;
- раздельные права руководителя и участника проекта.


## Проверка сохранения и связей операций

При сохранении операции приложение теперь проверяет, что элемент действительно создан в `PF · Операции`. Для привязки к проекту и статье используются технические ID как основной источник, а удобные поля `Проект` и `Статья` — как резервный источник для записей, внесённых вручную непосредственно в универсальных списках. Это позволяет корректно отображать одну и ту же операцию и в приложении, и в списках Битрикс24.
