# Финансы проектов для Битрикс24

Веб-приложение для ручного совместного учёта доходов и расходов по проектам внутри Битрикс24.

## Демо

https://nataliaer9.github.io/bitrix24-project-finance/

## Что умеет приложение

- создание проектов и добавление сотрудников;
- ручной учёт доходов и расходов;
- пользовательские статьи доходов и расходов;
- автоматический расчёт прибыли и рентабельности;
- цветные статусы финансового состояния проектов;
- фильтрация журнала операций;
- совместная работа нескольких сотрудников;
- хранение данных в универсальных списках Битрикс24;
- двусторонняя синхронизация приложения и списков Битрикс24;
- демо-режим при запуске вне Битрикс24;
- автоматическая первичная настройка хранилища.

## Архитектура

Приложение реализовано как **статическое локальное приложение Битрикс24**.

Отдельный backend и отдельная база данных не требуются. Данные хранятся в трёх универсальных списках Битрикс24:

1. `PF · Проекты`
2. `PF · Статьи`
3. `PF · Операции`

Работа с данными выполняется через REST API Битрикс24. Благодаря этому несколько сотрудников могут работать с одними и теми же данными внутри портала.

Подробности находятся в файле `AI_USAGE.md`.

## Цветные статусы проектов

Статус рассчитывается автоматически по фактическим операциям и не требует ручного заполнения:

- **Прибыльный** — прибыль неотрицательная, рентабельность 20% и выше;
- **На контроле** — проект не убыточный, но рентабельность ниже 20%;
- **Убыточный** — расходы превышают доходы;
- **Нет данных** — по проекту ещё нет финансовых операций.

## Финансовые расчёты

### Прибыль

`Прибыль = Доходы − Расходы`

### Рентабельность

`Рентабельность = Прибыль / Доходы × 100%`

Если доход равен нулю, рентабельность не вычисляется и в интерфейсе показывается `—`.

В `financial.js` дополнительно рассчитывается ROI:

`ROI = Прибыль / Расходы × 100%`

### Почему суммы хранятся в копейках

Финансовые суммы переводятся в целое число копеек до сохранения. Например:

`1234,56 ₽ → 123456`

Так расчёты не зависят от ошибок двоичной арифметики JavaScript с дробными числами.

## Быстрый запуск без Битрикс24

Можно открыть опубликованную демо-версию:

https://nataliaer9.github.io/bitrix24-project-finance/

Также можно открыть `index.html` локально в браузере.

Если приложение запущено как самостоятельная страница, а не внутри Битрикс24, автоматически включается демо-режим с тестовыми проектами и сохранением изменений в `localStorage`.

## Запуск внутри Битрикс24

1. Создайте ZIP-архив, в корне которого находятся:
   - `index.html`
   - `styles.css`
   - `financial.js`
   - `app.js`
2. В Битрикс24 откройте раздел разработчика локальных приложений.
3. Создайте **статическое локальное приложение** и загрузите ZIP.
4. Выдайте приложению права:
   - `lists` — работа с универсальными списками;
   - `user_brief` или более широкий `user` — работа с сотрудниками.
5. Первый запуск выполните администратором.
6. Нажмите **«Инициализировать приложение»**.
7. После создания списков приложение готово к работе.

## Двусторонняя синхронизация со списками Битрикс24

Приложение и универсальные списки работают с одними и теми же записями — отдельные копии данных не создаются.

- запись, созданная в приложении, сразу создаётся или обновляется в `PF · Проекты`, `PF · Статьи` или `PF · Операции`;
- запись, созданная вручную в списке Битрикс24, попадает в приложение после нажатия **«Обновить данные»** или перезагрузки страницы;
- при редактировании операции в приложении обновляются как пользовательские, так и служебные поля совместимости.

Для ручной работы в списках используются понятные поля:

### `PF · Статьи`

- название;
- тип статьи: **Доход / Расход**.

### `PF · Операции`

- проект;
- тип: **Доход / Расход**;
- статья;
- сумма, ₽;
- дата;
- комментарий.

Служебные поля `PROJECT_ID`, `TYPE`, `CATEGORY_ID`, `AMOUNT_CENTS` сохраняются для совместимости с существующими данными.

## Проверка сохранения и связей операций

При сохранении операции приложение проверяет, что элемент действительно создан в `PF · Операции`.

Для привязки к проекту и статье технические ID используются как основной источник, а пользовательские поля `Проект` и `Статья` — как резервный источник для записей, внесённых вручную непосредственно в универсальных списках.

Это позволяет корректно отображать одну и ту же операцию как в приложении, так и в списках Битрикс24.

## Тесты

Для проверки финансового модуля нужен только Node.js:

```bash
node tests/financial.test.js
```

Дополнительные npm-пакеты не требуются.

Ручные сценарии проверки находятся в `TESTING.md`.

## Ограничения тестовой версии

- валюта интерфейса — RUB;
- разграничение доступа внутри отдельных проектов не реализовано;
- сотрудники, имеющие доступ к спискам приложения, видят общий финансовый учёт;
- для промышленной версии стоит добавить аудит изменений, архивирование проектов, экспорт и проектные роли.
