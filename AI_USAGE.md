# Использование ИИ при разработке

В задании отдельно оценивается не только использование ИИ, но и способность проверить его результат. Поэтому ИИ использовался как ускоритель разработки, а не как источник непроверенного кода.

## Для чего использовался ИИ

- декомпозиция требований;
- выбор архитектуры без отдельного backend;
- подготовка структуры интерфейса;
- генерация первоначального JavaScript и CSS;
- перечисление граничных случаев финансовых расчётов;
- подготовка тестового чек-листа.

## Что было проверено вручную

1. Архитектура сверена с актуальной REST-документацией Битрикс24:
   - статические локальные приложения;
   - `lists.*`;
   - `user.current`;
   - `BX24.selectUsers`.
2. Денежные суммы переведены в целые копейки, чтобы не суммировать дробные `Number`.
3. Формула рентабельности явно зафиксирована в README и интерфейсе.
4. Написаны отдельные автоматические тесты финансового модуля.
5. Добавлены проверки целостности:
   - нельзя удалить проект с операциями;
   - нельзя удалить используемую статью;
   - нельзя удалить обязательную системную статью;
   - статья операции обязана соответствовать типу «доход/расход».
6. Приложение имеет независимый демо-режим для проверки интерфейса без портала.

## Решения, которые не были оставлены «как сгенерировал ИИ»

Первоначально очевидным вариантом был отдельный backend с БД. Для тестового задания это увеличивает количество точек отказа и усложняет запуск. После проверки возможностей Bitrix24 выбран вариант с универсальными списками как общим хранилищем.

Также финансовые значения не хранятся как дробные рубли: вместо этого сохраняется целое число копеек. Это снижает риск ошибок расчётов и делает проверку результата воспроизводимой.
